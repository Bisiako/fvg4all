OCR Test Bench

Confronta TrOCR (Transformers.js) e PaddleOCR / PP-OCR (RapidOCR) su una locandina di evento — CPU only.

1. Immagine di test

Trascina qui una locandina (JPG/PNG, fino a 5MB) oppure clicca per scegliere un file

1b. Immagini da GitHub Pages

GitHub Pages non permette di elencare una cartella, quindi l'elenco arriva dall'API di GitHub (repo Bisiako/fvg4all, branch main); le immagini si caricano da Pages. Clicca una miniatura per usarla come immagine di test qui sopra. Senza token l'API consente 60 richieste/ora.

3. Florence-2 — OCR su tutta l'immagine (VLM)

Quantizzazione (dtype)
Task

Modello onnx-community/Florence-2-base, girato nello stesso worker.js (CPU/wasm). A differenza di TrOCR non serve un passaggio di detection separato: legge da solo tutti i blocchi di testo sparsi nella locandina (titolo, date, luogo). Prima esecuzione più lenta (download modello, alcune centinaia di MB), poi cache del browser.

4. RapidOCR / PP-OCR — detection fai-da-te + recognition (sperimentale)

Dizionario di riconoscimento

Nessun pacchetto JS ufficiale: qui gira detection scritta a mano (soglia + bounding box assiali, niente rotazione) sopra i pesi ONNX di PP-OCRv4 + onnxruntime-web. Prima esecuzione lenta (scarica ~15-20MB tra detection e recognition). Se la console mostra errori di versione onnxruntime-web o di mismatch degli output, è il primo posto da controllare.
